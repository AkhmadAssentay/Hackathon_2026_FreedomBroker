# Звонки: проблемы, подходы из литературы, наши эксперименты

Звонки — самый слабый срез (на эталоне чатов ошибок 7–12%, на звонках — около 25%). Эталон звонков: все 5 реальных
звонков DEV × 8 критериев = **40 меток** (`eval/gold_calls.json`). Это очень мало: доверительные интервалы ±10 п.,
выводы — ориентир, а не гарантия. Воспроизвести: `python -m eval.calls run <вариант>`, `python -m eval.calls report`.

## 1. Что говорит литература: ограничения и предложенные решения

| Проблема | Работа | Что предлагают | Их ограничение |
|---|---|---|---|
| Ошибки распознавания речи портят оценку | [HyPoradise (NeurIPS 2023)](https://arxiv.org/pdf/2309.15701), [GenSEC challenge 2024](https://arxiv.org/pdf/2409.09785) | Генеративная коррекция (GER): LLM исправляет текст по нескольким гипотезам распознавания (N-best) | LLM подменяет услышанное языковыми «привычками»; избыточные почти одинаковые гипотезы сбивают модель |
| То же | [ClozeGER (2024)](https://arxiv.org/pdf/2405.10025) | Ограниченная коррекция: исправлять только там, где гипотезы расходятся | Нужен звук или хорошие гипотезы |
| Ошибки на именах, номерах, адресах почты | [Auto Review (2025)](https://arxiv.org/html/2506.05400v1), [бенчмарк LLM-судей голосовых агентов](https://arxiv.org/pdf/2608.24314) | Второй этап проверки, оценивать качество текста до доверия оценке | — |
| Перепутанные говорящие | [DiarizationLM (Interspeech 2024)](https://arxiv.org/pdf/2401.03506) | LLM исправляет разметку говорящих после диаризации | Обучение на Fisher/Callhome (англ.) |
| Оценка тона и эмоций по звуку | [AudioJudge (EACL 2026)](https://arxiv.org/pdf/2507.12705), [ParaPairAudioBench](https://arxiv.org/pdf/2606.24648) | Аудио-LLM как судья | Почти случайный уровень на паралингвистике, отставание от людей ~30 п. |

## 2. Что мы адаптировали и проверили

| Вариант | Идея из литературы | Как сделано у нас |
|---|---|---|
| **Правила звонка + факты** | структура разговора; измерять, а не спрашивать аудио-модель (AudioJudge) | код вычисляет: когда подключился оператор, первая реплика после этого, кто завершил звонок, реплики оператора после конца звонка, удержание; по записи — тишина с флагом «оператор предупредил»; правила из чек-листа для звонков (прощание «благодарю за обращение», клиент положил трубку → N/A, переспрос из-за связи — не вина оператора) |
| **Две гипотезы** | N-best (HyPoradise) | к каждой реплике — вторая расшифровка Whisper large-v3-turbo (GPU), цитировать можно только оригинал |
| **Ограниченная коррекция (GER)** | ClozeGER | локальная Qwen исправляет только расхождения гипотез, маски сохраняет, имён и цифр не добавляет |
| **Маршрут по каналу** | маршрутизация по критериям | «Консультация» в звонках → Sonnet (выбор leave-one-call-out: решение для каждого звонка — по остальным четырём) |
| **Разговор с коллегой на удержании** | DiarizationLM (разметка говорящих) | по системным событиям удержания такие реплики помечаются внутренними и не оцениваются |

**Рабочий прогон после внедрения** (правила звонка + факты + «Консультация» → Sonnet), три независимых прогона:
75.0%, 77.5%, 75.0% → **в среднем 75.8%** (было 72.5%), ошибка итога в среднем ≈ 9 баллов (было 9.7).
Лучший экспериментальный вариант — 80.0% (32/40), ошибка итога 5.9. Разброс между прогонами (±1–2 метки) — следствие
голосования с температурой и всего 5 звонков.

## 4. Выводы

1. **Помогло:** знание структуры звонка и измеренные по записи факты (+7.5 п. у Qwen, +5 п. у Sonnet), маршрут
   «Консультации» звонков в Sonnet (+2 метки). Это и внедрено.
2. **Не помогло:** вторая расшифровка Whisper (−2…−5 п.) и ограниченная коррекция GER (±0) — шумная вторая гипотеза
   сбивает модель так же, как избыточные N-best в HyPoradise; наши ошибки — не в словах, а в трактовке правил.
3. **Найден риск приватности:** Whisper «слышит» то, что организаторы замаскировали ([Имя скрыто] → произнесённое имя).
   Поэтому текст Whisper используется **только с локальной моделью на своём GPU**, никогда не отправляется во внешний
   API и не показывается в интерфейсе.
4. **Аудио-LLM как судья тона не использовали:** по AudioJudge это почти случайный уровень; вместо этого — измеримые
   признаки (тишина, доля речи, темп, удержание) как подсказки модели и проверяющему.

## 5. Что остаётся и как закрыть

| Ограничение | Решение |
|---|---|
| 5 размеченных звонков (±10 п.) | разметить ≥50 звонков; активное обучение: сначала те, где Sonnet и Qwen расходятся |
| Шумный исходный ASR | на своём GPU: Whisper large-v3 с VAD и пословными метками (faster-whisper/WhisperX) как основной текст |
| Нет диаризации у Whisper | pyannote-диаризация + LLM-исправление говорящих (DiarizationLM) |
| Казахские фрагменты и code-switching | модель распознавания, обученная на казахском (ISSAI KSC2), для KZ-участков |
| Тон и вежливость голосом | просодия (Parselmouth: высота, громкость, перебивания) как подсказка проверяющему, без балла |
